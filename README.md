# SIPflow

SIP-софтфон для macOS: компактне вікно в дусі «Телефона» з iPhone — круглі клавіші
з літерами, велика зелена кнопка виклику, «Останні» з пропущеними червоним. Стек
той самий, що в MicroSIP — [pjsip](https://www.pjsip.org/), — інтерфейс на SwiftUI.

## Можливості

- Кілька SIP-акаунтів одночасно: додавання, видалення, вмикання/вимикання, вибір типового для вихідних дзвінків
- Реєстрація акаунта: UDP / TCP / TLS, окремий auth ID, registrar, вихідний проксі, STUN, ICE
- Вихідні та вхідні дзвінки, кілька одночасних дзвінків
- Керування розмовою: мікрофон, утримання, DTMF, сліпий перевід і перевід із консультацією
- Телефонна книга: пошук, обрані, дзвінок у клік, додавання прямо з журналу.
  Ім'я з книги підставляється в картку дзвінка, журнал і сповіщення
- Журнал дзвінків (вхідні / вихідні / пропущені) з повторним набором
- Пропущені видно навіть після відходу від комп'ютера: значок у рядку меню
  з лічильником, бейдж у Dock і сповіщення з кнопкою «Передзвонити»
- Вибір мікрофона й динаміків, налаштування ехоподавлення та пріоритетів кодеків
- SRTP (опційно чи обов'язково), режим «Не турбувати», автовідповідь
- Спливаюча панель вхідного виклику з кнопками «Відповісти» / «Відхилити»,
  коли вікно згорнуте або застосунок у фоні
- Вікно логів pjsip для діагностики

## Встановлення

### Збірка з джерел — основний спосіб

Локально зібраний застосунок **не потрапляє в карантин** і запускається без
жодних діалогів Gatekeeper. Потрібні Command Line Tools (повний Xcode не
обов'язковий):

```sh
brew install pjproject
git clone https://github.com/OWNER/sipflow && cd sipflow
./Scripts/make-signing-identity.sh   # один раз
./Scripts/build.sh
open build/SIPflow.app
```

`make-signing-identity.sh` створює самопідписаний сертифікат «SIPflow Local
Signing» у в'язці login. Крок необов'язковий, але бажаний: без нього збірка
підписується ad-hoc, а такий підпис змінюється при кожній перезбірці — macOS
вважає нову збірку іншою програмою і щоразу перепитує доступ до мікрофона й до
пароля в Keychain. Зі сталим сертифікатом вимога підпису лишається незмінною:

```
designated => identifier "com.sipflow.app" and certificate root = H"…"
```

### Через Homebrew — зручніше, але з одним ручним кроком

```sh
brew tap OWNER/sipflow
brew install --cask sipflow
xattr -dr com.apple.quarantine /Applications/SIPflow.app
```

Третій рядок потрібен один раз. Застосунок підписано самопідписаним
сертифікатом і не нотаризовано, тому Gatekeeper блокує завантажений архів.
Прапорця `--no-quarantine` більше немає — Homebrew 6 його прибрала.

Прибрати цей крок може лише Developer ID із нотаризацією, а це платне членство
в Apple Developer Program. Для відкритого проєкту дешевший і чистіший шлях —
збірка з джерел.

### Вимоги

- macOS 15 або новіша
- **Тільки Apple Silicon**: pjproject із Homebrew постачається як `arm64`.
  Для Intel потрібно збирати pjsip із джерел під x86_64 і робити універсальний
  бінарник.

## Ліцензія

**GPL-3.0-or-later** — див. [`LICENSE`](LICENSE).

Версія саме третя, і це не довільний вибір: PJSIP дозволяє «GPLv2 або пізнішу»,
але OpenSSL 3 має ліцензію Apache 2.0, несумісну з GPLv2. Оскільки застосунок
лінкує обидві бібліотеки, GPLv3 — єдиний несуперечливий варіант. Подробиці
в [`Resources/ACKNOWLEDGEMENTS.md`](Resources/ACKNOWLEDGEMENTS.md).

## Випуск

```sh
GITHUB_OWNER=ваш-логін ./Scripts/release.sh
```

Скрипт збирає застосунок, **перевіряє, що він не залежить від бібліотек поза
системними** (інакше архів не запуститься на чужій машині), пакує `.app` через
`ditto` зі збереженням підпису, рахує sha256 і оновлює готовий файл каска
в [`Distribution/homebrew-sipflow`](Distribution/homebrew-sipflow).

OpenSSL лінкується статично саме заради цього: інакше застосунок вимагав би
Homebrew за жорстким шляхом `/opt/homebrew/opt/openssl@3`.

Офіційний `homebrew-cask` такий проєкт поки не прийме: для самоподання там
потрібні 90 форків, 90 стежників і 225 зірок. Власний tap працює одразу й без
жодних вимог.

### Іконка

Складається [`Scripts/make-icon.swift`](Scripts/make-icon.swift): градієнтна
підкладка плюс гліф `phone-incoming-fill` із набору
[Phosphor Icons](https://phosphoricons.com) (MIT). Вихідний SVG, готовий PNG
і текст ліцензії лежать у `Resources/icon`, тож збірка не потребує рендерера SVG.

SF Symbols в іконці навмисно не використовуються: ліцензія Apple дозволяє їх
в інтерфейсі застосунку, але забороняє в іконках, логотипах і торгових марках.

## Структура

| Шлях | Призначення |
| --- | --- |
| `Sources/CPJSIP` | Модуль-містток до заголовків pjsip |
| `Sources/SIPCore` | Обгортка над pjsua: акаунт, дзвінки, аудіопристрої, кодеки |
| `Sources/SIPflow` | Застосунок: SwiftUI-інтерфейс, налаштування, журнал |
| `Scripts` | Збірка bundle та генерація іконки |

Усі виклики pjsua йдуть з одного виділеного потоку (`PJWorker`), зареєстрованого в
pjlib; події повертаються в інтерфейс на головній черзі.

## Діагностика

Налаштування → Додатково → «Записувати SIP-лог у файл» пише повний обмін пакетами
у `sipflow.log` поруч із налаштуваннями (потрібен рівень логів 4 або вище).
Той самий потік видно у вкладці «Лог». Запис веде сам застосунок, а не pjsua:
її вбудований записувач відкриває файл без обрізання і без flush, через що в
одному файлі змішуються записи різних запусків.

## Дані застосунку

`~/Library/Application Support/SIPflow/` — `settings.json` і `history.json`.
Пароль SIP зберігається в Keychain, а не у файлі налаштувань.

## Мова інтерфейсу

Застосунок іде за мовою системи: українська, англійська, російська. Ключами
перекладу є самі українські рядки, тож код лишається читабельним, а якщо
перекладу бракує — видно осмислений текст, а не ідентифікатор.

Переклади: `Resources/{uk,en,ru}.lproj/Localizable.strings`, вони копіюються
в бандл під час збірки. SwiftUI перекладає лише літерали, передані напряму
(`Text("Набір")`), тому весь текст пропущено через `L()` з
[`Localization.swift`](Sources/SIPCore/Localization.swift) — інакше рядки, що
приходять із моделей, лишалися б неперекладеними.

Перевірити іншу мову без зміни системних налаштувань:

```sh
open build/SIPflow.app --args -AppleLanguages '("en")'
```

## Рингтони

П'ятнадцять мелодій, які застосунок **синтезує сам** — від класичних телефонних
каденцій різних країн до маримби, дзвіночка й арпеджіо. Опис кожної — це
послідовність тонів із огинаючою ([`Ringtone.swift`](Sources/SIPflow/Models/Ringtone.swift)),
а звук рахується семпл за семплом ([`RingtoneSynth.swift`](Sources/SIPflow/Models/RingtoneSynth.swift)).

Так немає ні ліцензійних питань до чужих записів, ні мегабайтів аудіо
в репозиторії. Синтез винесено окремо від програвача й без залежності від
AVFoundation — щоб той самий код можна було прогнати офлайн і перевірити.

Вибір і прослуховування — Налаштування → Аудіо → Дзвінок.

## Оформлення

Налаштування → Додатково → Інтерфейс:

- **Колір** — одинадцять акцентних кольорів (синій, блакитний, бірюзовий, зелений,
  жовтий, помаранчевий, червоний, рожевий, фіолетовий, індиго, графітовий).
  Перемикається на льоту, без перезапуску. Смислові кольори не змінюються:
  зелений «відповісти», червоний «відхилити» й червоний для пропущених несуть
  значення, а не оформлення.
- **Оформлення** — Системна / Світла / Темна. Задається на рівні застосунку
  (`NSApp.appearance`), тому охоплює і вікно налаштувань, і панель дзвінка.

Поле набору — `NSTextField` із прозорим курсором ([`CursorlessField`](Sources/SIPflow/Views/CursorlessField.swift)),
а не текст із власним обробником клавіш: так над клавіатурою немає миготливої
риски, але лишається все, що очікується від поля — введення з клавіатури,
вставка, скасування, виділення.

Кнопка виклику поводиться як на телефоні: при заповненому полі дзвонить, при
порожньому підставляє останній набраний номер.

## Кілька акаунтів

Акаунти додаються й видаляються на живому стеку pjsip: додавання другого акаунта
не рве активні дзвінки на першому. Видалення знімає акаунт із реєстрації
(`REGISTER … Expires: 0`) і прибирає пароль із Keychain. Перезапуск стеку потрібен
лише при зміні глобальних параметрів — порту, STUN/ICE, частоти дискретизації,
ехоподавлення чи рівня логів.

Транспорт створюється по одному на тип і спільний для акаунтів. Якщо задано
фіксований локальний порт, TLS слухає наступний за ним, бо з TCP вони не можуть
займати той самий.

## Спливаюча панель вхідного виклику

Коли вікно згорнуте, закрите або застосунок у фоні, вхідний дзвінок показується
власною панеллю у правому верхньому куті — з іменем абонента й кнопками
«Відповісти» / «Відхилити». Вона з'являється поверх інших вікон, не забирає фокус
у програми, з якою працює оператор, і зникає, щойно на дзвінок відповіли або він
завершився.

Це саме власне вікно, а не системний банер. Системні сповіщення для дзвінка
виявилися ненадійними: macOS приймає їх через API без жодної помилки й може не
вивести на екран — через режим фокусування, стиль сповіщень або відкликаний
дозвіл. Для вхідного виклику така мовчазна відмова неприпустима, тому панель
не залежить ні від дозволів, ні від «Не турбувати».

Системні сповіщення лишилися там, де вони доречні — для пропущених дзвінків.

Стан «на передньому плані» знімається до того, як застосунок почне привертати
увагу до себе: `NSApp.requestUserAttention` робить застосунок активним, і перевірка
після нього хибно вирішувала, що вікно й так на екрані.

## Коли клієнт «онлайн», а вхідних немає

Два стани, які ззовні виглядають однаково добре, але вхідні дзвінки не доходять —
обидва застосунок тепер розпізнає й показує:

- **Сервер не зберіг нашу прив'язку.** У відповідь на REGISTER приходить `200 OK`,
  але нашої адреси серед збережених Contact немає — таке буває, коли на акаунті
  вичерпано ліміт одночасних реєстрацій, а місця зайняті сесіями, які ще не
  спливли. Застосунок звіряє свою адресу (порт NAT із `received`/`rport` у Via)
  зі списком у відповіді, показує «Онлайн, але вхідні не надходитимуть» і
  повторює спробу кожні 30 секунд, доки місце не звільниться.
- **Реєстрацію відхилено.** Наприклад `403 Forbidden` з тієї ж причини. Типова
  поведінка pjsua — мовчати 5 хвилин до наступної спроби; тут перша повторна
  спроба йде через 8 секунд, далі кожні 30.

Кожен запуск застосунку займає одну реєстрацію на сервері приблизно на 5 хвилин,
навіть якщо процес завершено примусово. Часті перезапуски під час розробки здатні
вичерпати ліміт провайдера.

## Пропущені дзвінки

Банер зникає сам, тож той, хто відходив від комп'ютера, його не побачить. Тому про
пропущений повідомляють три незалежні канали:

1. **Значок у рядку меню** біля годинника — постійний, показує стан реєстрації, а
   при пропущених стає червоним із лічильником. У меню — список пропущених із
   часом, дзвінок у клік і «Позначити переглянутими».
2. **Цифра на іконці в Dock** — червоне коло з кількістю, як непрочитані листи в Пошті.
   Плитка Dock малюється власним кодом (`DockBadgeView`): штатний
   `NSDockTile.badgeLabel` у цій збірці нічого не показував, хоча значення приймав
   без помилки. Видно, коли Dock на екрані — при автоприховуванні Dock треба
   спершу відкрити.
3. **Сповіщення про пропущений** із дією «Передзвонити». На відміну від банера про
   вхідний, воно лишається в центрі сповіщень.

Перші два канали не залежать від дозволу на сповіщення. Лічильник гасне, коли
оператор відкриє вкладку «Журнал» або натисне «Позначити переглянутими».

Номери зіставляються за останніми дев'ятьма цифрами, тож `380955158408`,
`0955158408` і `+38 (095) 515-84-08` — той самий контакт.

## Обмеження поточної версії

- Немає BLF/presence і SIP-чату
- Немає кодека Opus: бібліотека з Homebrew зібрана без нього
- Якщо сталий сертифікат не створено, підпис ad-hoc змінюється при кожній
  перезбірці, і macOS перепитує доступ до мікрофона й до пароля в Keychain.
  Поки запит не підтверджено, акаунт не реєструється — у шапці про це прямо
  написано, а індикатор стає червоним
